# 背景

## AIを導入しただけでは生産性向上につながりません

生成AIやAIコーディングツールを導入しても、利用が個人のプロンプト入力にとどまる場合、効果は個人の知識や経験に依存します。成果物の形式、確認方法、品質基準が統一されていなければ、生成時間が短縮されても、確認や修正の工数が増える可能性があります。

AIがファイル、リポジトリ、Issue、CI/CD、テスト環境へ接続されていない場合、利用者が情報をコピーし、AIの出力を手作業で反映する必要があります。工程間の待ち時間や転記作業が残り、案件全体への効果は限定されます。

標準となるフレームワークの利用方法、動作するテンプレートリポジトリ、共通の方式設計がなければ、AIは認証、例外処理、ログ出力、データアクセスなどの方式を作業のたびに判断することになります。

## 「AIを利用している」では状態を比較できません

同じ「AI利用」でも、実態は大きく異なります。区別せずに利用率だけを測ると、利用人数や実行回数が増えていても、案件全体の生産性や品質が向上しているかを判断できません。

## 工程ごとに成熟度が異なります

SI受託開発では、実装工程でAI利用が進んでいても、外部設計、結合テスト、レビューが人手中心のままであることがあります。実装時間だけが短縮されると、後続工程が処理できる量を超え、レビュー待ちやテスト待ちが増えます。

## 管理プロセスが追いついていません

資産と環境を整備しても、WBSや見積もりが従来のままでは、効果を計画にも収支にも反映できません。AIの生成量に対して人の確認容量が不足すれば、確認工程が制約になります。契約形態によっては、工数削減が売上減につながります。

このため本モデルは、AIが使う資産と能力（Agent Skill、環境との接続、開発標準資産）に加えて、管理プロセス（開発プロセス、見積もり・PJ収支）を評価軸に含めています。
