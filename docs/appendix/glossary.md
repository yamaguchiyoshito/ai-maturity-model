# 用語集

本成熟度モデルで使う用語と、説明に繰り返し出てくる開発・契約の基本用語です。基本用語の詳しい説明は[開発の基本用語](../guide/terms.md)に、AIエージェントとSkillの説明は[AIを含む開発とは](../guide/ai-development.md)にあります。

## 本成熟度モデルの用語

| 用語 | 意味 | 詳しく説明しているページ |
|---|---|---|
| PJ | プロジェクト。本成熟度モデルの評価単位 | [判定規則](../model/rules.md) |
| 架空PJ（販売管理PJ） | 説明の「具体例（架空PJ）」で一貫して使う架空の販売管理システム更改PJ。製造業の販売部門向け、請負、10名体制 | [はじめに](../guide/index.md) |
| 制度化レベル | プロセスがどれだけ定着し、再現できるかを表す、レベル1〜5の段階 | [成熟度モデルの全体像](../guide/overview.md) |
| 評価軸 | 何を見るかの観点。Agent Skill、環境との接続、開発標準資産、AI前提の開発プロセス、AI前提の見積もり・PJ収支の5つ | [軸別ビュー](../model/axes.md) |
| 自動化段階 | AIがどこまで人手を介さず実行するかを表す、A1〜A4の段階 | [自動化段階](../model/automation.md) |
| 統制不足 | 自動化段階が、前提とするレベルを超えている状態 | [自動化段階](../model/automation.md) |
| Agent Skill | AIエージェントが再利用する、手順・判断基準・品質基準・成果物形式をファイルに書いたもの | [AIを含む開発とは](../guide/ai-development.md) |
| 環境との接続 | AIが開発環境から情報を取得し、変更、実行、検証、記録まで行える範囲と、その権限 | [AIを含む開発とは](../guide/ai-development.md) |
| 開発標準資産 | 標準フレームワーク、テンプレートリポジトリ、方式設計の総称 | [AIを含む開発とは](../guide/ai-development.md) |
| 接続キット | 権限設定、CI定義、エージェント実行基盤をまとめた組織標準の構成 | [軸別ビュー](../model/axes.md) |
| 確定 | 証拠で確認できた判定結果 | [判定規則](../model/rules.md) |
| 暫定上限 | ヒアリング未了の基準をすべて充足とみなした場合の判定結果 | [判定規則](../model/rules.md) |
| 要ヒアリング | リポジトリ外に証拠がありうるため、確認が必要な基準の状態 | [判定規則](../model/rules.md) |
| 申告 | 回答者、回答内容、証拠の所在を記録したヒアリング回答 | [判定規則](../model/rules.md) |
| 制約工程 | 案件全体のリードタイムや品質を決めている工程 | [評価の進め方](../assess/howto.md) |
| 工程性能ベースライン | 複数PJの実績から求めた、工程の通常の性能範囲 | [レベル別ビュー](../model/levels.md) |
| 帰属ルール | 削減効果を、価格還元・利益・品質への再投資のどれに充てるかの取り決め | [軸別ビュー](../model/axes.md) |
| 基準工数 | AIを使わない場合の工数。効果算定の分母になる | [算定式](../effect/formula.md) |
| 按分 | 複数の作業やPJにまたがる工数を、利用した割合で割り振ること | [算定式](../effect/formula.md) |

## 開発の基本用語

| 用語 | 意味 | 詳しく説明しているページ |
|---|---|---|
| AIエージェント | 作業環境の中でファイルを読み、書き、コマンドを実行し、結果を見て次の行動を決めるAIのプログラム | [AIを含む開発とは](../guide/ai-development.md) |
| プロンプト | AIへの指示文。Skillとの違いは、保存されず再利用されないこと | [AIを含む開発とは](../guide/ai-development.md) |
| リポジトリ | ソースコード、設定、文書を変更履歴ごと保管する場所 | [開発の基本用語](../guide/terms.md#変更と履歴) |
| コミット | リポジトリへの変更を、理由とともに記録する単位 | [開発の基本用語](../guide/terms.md#変更と履歴) |
| ブランチ | 本線に影響を与えずに変更を進めるための作業用の分かれ道 | [開発の基本用語](../guide/terms.md#変更と履歴) |
| MR・PR | マージリクエスト、プルリクエスト。変更を本線へ取り込みたいという提案。レビューの単位 | [開発の基本用語](../guide/terms.md#変更と履歴) |
| マージ | 変更の提案を本線へ取り込むこと | [開発の基本用語](../guide/terms.md#変更と履歴) |
| ブランチ保護 | 本線への取り込みに、レビュー承認や必須の自動検証を共有環境の設定で強制する仕組み | [開発の基本用語](../guide/terms.md#変更と履歴) |
| Issue | 課題、要望、作業項目を一件ずつ記録する票 | [開発の基本用語](../guide/terms.md#作業の管理) |
| WBS | 作業分解構成。PJの作業を工程と作業項目に分解した一覧 | [開発の基本用語](../guide/terms.md#作業の管理) |
| 工数 | 作業にかかる人の時間。人日、人月で数える | [開発の基本用語](../guide/terms.md#作業の管理) |
| 受入基準 | 成果物を「できた」とみなす条件 | [開発の基本用語](../guide/terms.md#作業の管理) |
| ビルド | ソースコードから動くプログラムを組み立てること | [開発の基本用語](../guide/terms.md#自動検証) |
| 静的解析 | プログラムを動かさずに、コードの問題を機械的に検出すること | [開発の基本用語](../guide/terms.md#自動検証) |
| 単体テスト | 小さな単位ごとに期待どおり動くかを確かめる自動テスト | [開発の基本用語](../guide/terms.md#自動検証) |
| ローカル事前検証 | 共有する前に、個人の作業環境で行うビルド・静的解析・テスト | [開発の基本用語](../guide/terms.md#自動検証) |
| CI・共有CI | 継続的インテグレーション。変更を合図に共有環境で自動的に検証する仕組み。共有CIはチームで共有しているCI環境 | [開発の基本用語](../guide/terms.md#自動検証) |
| 必須ジョブ | 合格しなければマージできないと定めた共有CIの検証 | [開発の基本用語](../guide/terms.md#自動検証) |
| 請負 | 成果物の完成に対価を受け取る契約。工数が減れば利益が増える | [開発の基本用語](../guide/terms.md#契約と収支) |
| 準委任 | 作業時間や体制の提供に対価を受け取る契約。工数が減れば売上が減る | [開発の基本用語](../guide/terms.md#契約と収支) |
| 人月 | 1人が1か月働く量を単位にした見積もりと価格の方式 | [開発の基本用語](../guide/terms.md#契約と収支) |
| PJ原価 | PJにかかる費用。人件費、AI利用料、基盤費を含む | [開発の基本用語](../guide/terms.md#契約と収支) |
| フレームワーク | アプリケーションの骨組みを提供するソフトウェア部品の集まり | [開発の基本用語](../guide/terms.md#標準と方式) |
| テンプレートリポジトリ | 新しいPJやモジュールの雛形として配布する、動く状態のリポジトリ | [開発の基本用語](../guide/terms.md#標準と方式) |
| 方式設計 | 認証、例外処理、ログ、データアクセスなど、システム共通の作り方の方針を定めた設計 | [開発の基本用語](../guide/terms.md#標準と方式) |
| ADR | 設計判断の記録。何を、なぜそう決めたかを一件ずつ残す文書 | [開発の基本用語](../guide/terms.md#標準と方式) |
| テーラリング | 組織標準を、PJの条件に合わせて調整すること。差分と理由を記録する | [開発の基本用語](../guide/terms.md#標準と方式) |
| ベースライン | 複数PJの実績から求めた「通常の範囲」 | [開発の基本用語](../guide/terms.md#標準と方式) |
