# SI受託開発のAI利用成熟度モデル

SI受託開発におけるAI利用の成熟度を、PJ（プロジェクト）単位で評価するためのモデルです。次の二つを目的とします。

1. **案件全体の生産性を制約している工程を特定する**
2. **生産性効果を、利用者アンケート以外の実績指標で測定する**

AIツールの導入数や利用人数では評価しません。5つの評価軸について、CMMIのレベル構成を参考にした5段階で制度化の度合いを判定し、別に自動化段階を記録します。

## 早見表

PJの状態は「レベル3／A3」のように、**制度化レベル**と**自動化段階**の組で表します。

| レベル | 名称 | 再現できる範囲 | 自動化段階の上限 |
|---|---|---|---|
| 未到達 | — | 再現できない | — |
| 1 | 属人的 | 本人 | A1 人が起動し、ローカルで実行 |
| 2 | プロセス確立 | PJ内 | A2 共有環境に接続し、MRまで作成 |
| 3 | 組織標準化 | 他のPJ | A3 サーバサイドで、イベント・スケジュール起動 |
| 4 | 定量管理 | 予測できる | A4 統制範囲内で自律反復 |
| 5 | 継続的最適化 | 改善し続ける | A4 自律範囲を実績で見直す |

## 5つの評価軸

| 軸 | 確認する問い |
|---|---|
| Agent Skill | AIが何を、どの手順と判断基準で行うかが定義されているか |
| 環境との接続 | AIが必要な情報を取得し、作業と検証を実行できるか |
| 開発標準資産 | AIと人が何に準拠して設計・実装するかが具体化されているか |
| AI前提の開発プロセス | 工程と人の役割が、AIの実行を前提に設計されているか |
| AI前提の見積もり・PJ収支 | AIの効果と費用が見積もりと収支に反映され、実績で検証されているか |

前の3軸はAIが使う「資産と能力」、後の2軸はそれを前提にPJを運営する「管理プロセス」です。

## このモデルの3つの原則

- **PJのレベルは5軸の最小値です。** 1軸だけ高くても、PJのレベルは上がりません。
- **自動化はレベルの範囲内で進めます。** レベルを超えた自動化は「統制不足」と記録します。
- **証拠で判定します。** 自己申告だけでは充足としません。
