# 判定規則

**前提となる用語：** [制度化レベル、評価軸、自動化段階](../guide/overview.md)、[リポジトリ、コミット、MR・PR、共有CI、ブランチ保護、WBS](../guide/terms.md)

このページは、レベルと自動化段階をどう決めるかの規則です。評価の実務の流れは[評価の進め方](../assess/howto.md)にあります。

## 評価単位

評価単位はPJです。複数チームで構成されるPJでは、チームごとの記録を同じPJにひもづけます。

## レベルの決め方

1. **軸別のレベル**：下位レベルを含むすべての基準を満たした最上位のレベルです。
2. **PJのレベル**：5軸の最小値です。
3. **自動化段階**：実行記録で確認できた最上位の段階です。
4. **確定と暫定上限**：証拠で確認できた結果を「確定」、ヒアリング未了の基準をすべて充足とみなした結果を「暫定上限」として併記します。
5. **レベル4・5**：PJ単独では判定しません。ベースラインは複数PJの実績から作るため、組織側の整備が到達条件です。

Agent Skill、環境との接続、開発標準資産、AI前提の開発プロセスは、主要工程ごとにも判定できます（[工程別チェックリスト](../process/index.md)）。見積もり・PJ収支は、見積もり時点と完了時点の2回、PJ単位で判定します。

## 証拠

自己申告だけでは充足としません。基準ごとに、次のいずれかを確認します。

| 証拠の種類 | 例 |
|---|---|
| リポジトリ内の成果物 | SKILL.md、CI定義、エージェントの権限設定、方式設計書、ADR |
| 実行記録 | コミット履歴、MR・PRの記録、共有CIのパイプライン記録 |
| 共有環境の設定 | ブランチ保護、必須ジョブ、承認ルール |
| リポジトリ外の文書 | WBS、見積書の内訳、原価記録、契約条件 |
| 申告 | 回答者、回答内容、証拠の所在を記録したヒアリング回答 |

申告だけで充足とした基準は、報告書で区別して表示します。

**販売管理PJなら**：「Skillの変更をレビューしている」という基準は、SkillのファイルへのMR・PRにレビュー承認の記録があれば「リポジトリ内の実行記録」で充足です。「見積もりにAI利用料を計上している」は、リポジトリの中には証拠がないので、見積書の内訳（リポジトリ外の文書）か、PMへのヒアリング回答（申告）で確認します。

## 判定の3状態

| 状態 | 意味 |
|---|---|
| 充足 | 証拠を確認した |
| 未充足 | 探索したが証拠がなかった（リポジトリで判定できる基準に限る） |
| 要ヒアリング | リポジトリ外に証拠がありうるため、確認が必要 |

リポジトリ外に証拠がありうる基準を、探索だけで「未充足」にはしません。

**確定と暫定上限の例**：販売管理PJのリポジトリを走査した結果、Agent Skill軸はレベル2の基準7件のうち5件が充足、2件が要ヒアリングだったとします。このとき確定レベルは1（レベル2の基準をすべて満たしたとは言えない）、暫定上限は2（要ヒアリングの2件が充足なら2になる）です。ヒアリングで2件とも充足と分かれば、確定レベルが2になります。

## 維持の条件と再評価

- 四半期ごと、または主要な開発フェーズの終了時に再評価します。
- レベル2以上は、直近四半期の実行記録がなければ、維持しているとは判定しません。Skill、接続環境、標準資産が存在するだけでは不十分です。

**次に読む：** [評価する](../assess/index.md)の節で、実際に評価を進める手順を確認します。
