# レベル別ビュー

各レベルについて、5つの評価軸がどのような状態にあるかを横断で読むためのページです。「次のレベルの全体像」を掴むときに使います。

| レベル | 名称 | 説明 |
|---|---|---|
| レベル1 | 属人的 | プロセスは未定義で場当たり的に運用されており、成功は主に個々の能力や努力に依存している。 |
| レベル2 | プロセス確立 | プロジェクトレベルで基本的な管理プロセスが確立され、計画・監視・制御によって再現可能な成果が得られている。 |
| レベル3 | 組織標準化 | 組織全体で標準化されたプロセスが定義・文書化され、全プロジェクトで一貫して適用されている。 |
| レベル4 | 定量管理 | プロセスのパフォーマンスが統計的手法により定量的に測定・制御されており、予測可能かつ安定した成果が得られている。 |
| レベル5 | 継続的最適化 | 継続的な改善と技術革新が組織文化として確立され、プロセスの有効性と適応力が継続的に向上している。 |

レベル1の条件を満たさない状態（AI未利用、単発利用）は、レベルを付けず「未到達」と記録します。

## レベル1：属人的

**全体像**：AIを使える個人がいるが、PJとしては何も決まっていない。効果は出ても測れない。

| 評価軸 | 状態 |
|---|---|
| Agent Skill | 個人が作成したSkillを本人が反復利用している |
| 環境との接続 | 個人のローカル環境で、ファイル変更、コミット、ビルド・テスト実行、結果取得ができる |
| 開発標準資産 | 動作する最小構成と起動・テスト手順を個人が保存している |
| AI前提の開発プロセス | 個人が自分の作業順序を変えている。WBSと完了条件は従来のまま |
| AI前提の見積もり・PJ収支 | 担当者が経験で係数を掛けている。AI利用料はPJ原価に入っていない |

- **自動化段階の上限**：A1
- **レベル2へ上がる条件**：本人以外が同じ結果を出せること。工数を記録していること。

## レベル2：プロセス確立

**全体像**：PJ内なら誰がやっても同じ結果になり、効果を測定できる。ただしPJごとに作り方が違う。

| 評価軸 | 状態 |
|---|---|
| Agent Skill | PJ共通のSkillを版管理し、変更をレビューし、出力を検証している。管理責任者と利用手順がある |
| 環境との接続 | 共有リポジトリ、Issue、共有CIに接続している。AIの権限と人間の承認が必要な操作を定義済み |
| 開発標準資産 | PJのフレームワーク、テンプレートリポジトリ、方式設計を定義し、複数メンバーが同じリリース版から開始できる |
| AI前提の開発プロセス | WBSにAI適用作業、人の確認点、受入基準を定義している。レビューとテストの処理容量をAIの生成量に合わせて計画している |
| AI前提の見積もり・PJ収支 | 見積もりにAI適用範囲、確認・修正工数、AI利用料、Skill保守費を明示計上している。基準工数を記録し、予実を対比している |

- **自動化段階の上限**：A2
- **レベル3へ上がる条件**：組織標準から開始していること。標準との差分・例外・承認を記録していること。

## レベル3：組織標準化

**全体像**：どのPJも組織標準から始まり、差分を説明できる。PJ間で実績を比較できる。

| 評価軸 | 状態 |
|---|---|
| Agent Skill | 組織共通のSkillを複数PJが利用している。品質・セキュリティ基準を内蔵し、Skill間で出力を受け渡す。PJの改変と理由を記録している |
| 環境との接続 | 組織標準の接続キット（権限、CI定義、エージェント実行基盤）を適用している。マージ停止条件と証跡保存が共有環境の設定で強制される |
| 開発標準資産 | 組織標準資産の採用版・個別変更・例外・承認理由を記録している。方式設計から実装例と検証方法をたどれ、自動判定できる制約はCIで検証している |
| AI前提の開発プロセス | 組織標準のAI前提プロセスからPJがテーラリングしている。工程間の成果物がAIの読める形式で受け渡され、人の役割が「承認と例外判断」として定義されている |
| AI前提の見積もり・PJ収支 | 組織標準の見積もりモデルを使っている。削減効果の帰属ルールが契約形態別に定義されている |

- **自動化段階の上限**：A3
- **レベル4へ上がる条件**：複数PJの実績からベースラインが作られていること。「異常」を数値で定義していること。

## レベル4：定量管理

**全体像**：結果を事前に予測でき、逸脱を数値で検知できる。この予測可能性があって初めて、AIに自律実行を任せられる。

| 評価軸 | 状態 |
|---|---|
| Agent Skill | Skill別に品質効果・生産性効果・運用コストのベースラインを持つ。初回合格率や修正回数が閾値を外れたSkillを検知している |
| 環境との接続 | CI初回成功率、再試行回数、待ち時間の管理限界を定義している。停止条件・再試行条件・人間への確認条件を数値で設定している |
| 開発標準資産 | 標準資産への適合率、逸脱件数、更新適用のリードタイムを測定し、目標値で管理している |
| AI前提の開発プロセス | 工程別の流量、待ち時間、手戻り率のベースラインを持つ。制約工程を数値で検知し、要員と自動化を再配分している |
| AI前提の見積もり・PJ収支 | 見積もりと実績の乖離を統計的に管理し、係数を実績ベースラインから設定している。収支予測を幅で提示できる |

- **自動化段階の上限**：A4
- **レベル5へ上がる条件**：改善の効果を前後比較で実証していること。改善が標準へ反映されていること。

## レベル5：継続的最適化

**全体像**：実績データが標準を書き換え続ける。AI自身が改善案を出し、人間が承認する。

| 評価軸 | 状態 |
|---|---|
| Agent Skill | 失敗事例と実行履歴からSkillの不足を特定し、AIが修正案を作成、人間がレビューして標準へ反映している |
| 環境との接続 | 実行履歴から接続・権限・起動条件を改善し、複数PJへ展開している |
| 開発標準資産 | 複数PJの実績から標準資産を改善し、互換性検証、配布、PJ側の更新まで継続している |
| AI前提の開発プロセス | 実績から工程構成そのものを再設計している（工程の統廃合、ゲート位置の変更） |
| AI前提の見積もり・PJ収支 | 実績から係数と価格モデルを継続更新している。人月以外の価格方式を検証し、標準へ反映している |

- **自動化段階の上限**：A4（自律範囲そのものを実績に基づいて拡大・縮小する）
- **判定単位**：レベル4・5はPJ単独では判定しません。組織側の整備が到達条件です。
