# 自動化段階

レベルは「プロセスがどれだけ制度化されているか」を表し、自動化段階は「AIがどこまで人手を介さず実行するか」を表します。この二つは別のものなので、分けて記録します。

[AIを含む開発とは](../guide/ai-development.md)で説明した「AIを使うの四つの姿」が、そのまま自動化段階に対応します。

| 段階 | 姿 | 販売管理PJなら |
|---|---|---|
| A1 | 手元で動かす | 開発者が自分のPCでAIを起動し、生成とテストをさせ、自分で確認してコミットする |
| A2 | 共有の場につなぐ | AIがIssueを読んで作業ブランチで変更し、変更の提案（MR・PR）を作る。PLがレビューしてマージする |
| A3 | 自動で起動する | Issueに「AI対応」のラベルが付くと、サーバ上でAIが起動し、変更、CIでの検証、結果の記録まで行う。人は結果を確認する |
| A4 | 自分で判断して繰り返す | AIが対象の作業に合うSkillを選び、CIが失敗すれば原因を直して再実行し、通常の範囲を外れたら止まって人に確認する |

## 段階の定義

| 段階 | 状態 | 前提とするレベル | 理由 |
|---|---|---|---|
| A1 | 人が起動し、ローカルで実行・検証する | レベル1 | 影響が個人環境に閉じる |
| A2 | 共有リポジトリ・Issue・共有CIに接続し、MRまで作成する | レベル2 | 権限と人間レビューが定義済みである必要がある |
| A3 | サーバサイドで、イベントやスケジュールを契機に実行・検証・記録する | レベル3 | 無人起動は、強制力のある組織標準の停止設定が前提 |
| A4 | 統制範囲内で、Skillと環境を選択し自律反復する | レベル4 | 停止・再試行条件は、ベースラインがなければ数値化できない |

A4は人間を排除する状態ではありません。人間が目的、権限、承認条件、停止条件を定め、その範囲内でAIが実行します。

## 統制不足

自動化段階が前提レベルを超えている状態を「統制不足」と記録します。例：レベル2のままA3を構築している。

ツール導入は制度の整備より先に進みやすいため、この状態は珍しくありません。統制不足のPJでは、自動化をそれ以上進めず、制約になっている軸のレベルを先に引き上げます。

## A4にレベル4が必要な理由

A4では、AIが異常を検知して停止し、再試行の可否と人間への確認要否を判断します。その判断基準となる停止条件・再試行条件は、「通常の範囲」が数値で分かっていなければ定義できません。通常の範囲とは、工程性能ベースライン（CI初回成功率、修正回数、待ち時間など）です。ベースラインのない自律実行は、根拠のない閾値で動くことになります。

## 見積もりとの関係

| 規則 | 内容 |
|---|---|
| 見積もりへの係数適用 | 見積もりで使える削減率は、他の4軸の最小レベルに対応する目安値を上限とする |
| 顧客へ確約できる時点 | 削減効果を価格や納期として確約できるのは、見積もり・PJ収支軸がレベル4以上の場合 |
