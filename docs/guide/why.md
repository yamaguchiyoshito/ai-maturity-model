# なぜ成熟度を測るのか

**前提となる用語：** [AIエージェント、Skill、環境との接続、開発標準資産](ai-development.md)、[MR・PR、レビュー、WBS、基準工数、請負と準委任](terms.md)

このページでは、AIを導入しただけでは生産性が上がらない理由を、販売管理PJで起きたことを追いながら説明します。本モデルが「AIツールの導入数や利用人数」ではなく「成熟度」を測る理由がここにあります。

## 販売管理PJで起きたこと

販売管理PJでは、開発者5名のうち2名が、個人の判断でコーディング用のAIエージェントを使い始めました。3か月後の状況は次のとおりでした。

| 観点 | 起きたこと |
|---|---|
| 実装の速さ | 2名の担当分は、WBSの予定より早く「実装完了」になった |
| レビュー | 2名が出す変更の提案（MR・PR）が週に3倍に増え、PLのレビュー待ちが常に10件を超えた。レビューの指摘は「例外処理の方式が他と違う」「ログの出し方が統一されていない」が多かった |
| テスト | 単体テストはAIが生成したが、何を確認しているテストなのかをテスト担当が読み解く時間が増えた |
| 他の3名 | 2名のやり方を知らない。1名は自分で試したが、設定の仕方が分からず止めた |
| 見積もりと収支 | 見積もりは従来の人月のまま。AIの利用料は誰かの立替えになっており、PJ原価に入っていない |
| 効果の説明 | 顧客と自社の上長から「AIでどれだけ効率化したのか」と聞かれたが、基準になる工数の記録がなく、答えられなかった |

実装工程だけが速くなり、レビューとテストが追いつかず、効果は測れない。これが、AIを「導入した」だけのPJの典型的な姿です。問題はAIの能力ではなく、PJの仕組みがAIを前提にしていないことにあります。

## AIを導入しただけでは生産性向上につながりません

生成AIやAIコーディングツールを導入しても、利用が個人のプロンプト入力にとどまる場合、効果は個人の知識や経験に依存します。成果物の形式、確認方法、品質基準が統一されていなければ、生成時間が短縮されても、確認や修正の工数が増える可能性があります。販売管理PJのレビュー待ちは、まさにこの状態です。

AIがファイル、リポジトリ、Issue、CI、テスト環境へ接続されていない場合、利用者が情報をコピーし、AIの出力を手作業で反映する必要があります。工程間の待ち時間や転記作業が残り、案件全体への効果は限定されます。

標準となるフレームワークの利用方法、動作するテンプレートリポジトリ、共通の方式設計がなければ、AIは認証、例外処理、ログ出力、データアクセスなどの方式を作業のたびに判断することになります。販売管理PJのレビュー指摘が方式のばらつきに集中したのは、このためです。

## 「AIを利用している」では状態を比較できません

同じ「AI利用」でも、実態は大きく異なります。販売管理PJの2名と、組織標準のSkillと接続環境を使うPJの開発者は、どちらも「AIを利用している」と答えます。区別せずに利用率だけを測ると、利用人数や実行回数が増えていても、案件全体の生産性や品質が向上しているかを判断できません。

## 工程ごとに成熟度が異なります

SI受託開発では、実装工程でAI利用が進んでいても、外部設計、結合テスト、レビューが人手中心のままであることがあります。実装時間だけが短縮されると、後続工程が処理できる量を超え、レビュー待ちやテスト待ちが増えます。PJ全体の速さを決めるのは、最も遅い工程です。本モデルが工程別の確認を持つのは、この「制約になっている工程」を見つけるためです。

## 管理プロセスが追いついていません

資産と環境を整備しても、WBSや見積もりが従来のままでは、効果を計画にも収支にも反映できません。AIの生成量に対して人の確認容量が不足すれば、確認工程が制約になります。契約形態によっては、工数削減が売上減につながります。販売管理PJは請負なので削減は利益になりますが、同じ組織の準委任のPJでは、同じ取り組みが売上を減らします。

このため本モデルは、AIが使う資産と能力（Agent Skill、環境との接続、開発標準資産）に加えて、管理プロセス（AI前提の開発プロセス、AI前提の見積もり・PJ収支）を評価軸に含めています。

## 本モデルが測ること

本モデルは、次の二つを目的に、PJの状態を測ります。

1. **案件全体の生産性を制約している工程を特定する。** 速くなった工程ではなく、追いつかない工程を見つけます。
2. **生産性効果を、利用者アンケート以外の実績指標で測定する。** 「便利になった」という感想ではなく、基準工数との差で測ります。

そのために、「どれだけ再現できる仕組みになっているか（制度化レベル）」を5つの観点（評価軸）で判定し、「AIがどこまで自分で動いているか（自動化段階）」を別に記録します。
