# はじめに

この節は、AIを含む開発に不慣れな方のために、成熟度モデルの本体を読む前に知っておくことをまとめた入門です。ツールや判定基準の話に入る前に、「AIを含む開発では何が起きているのか」「なぜ成熟度という考え方が必要なのか」「この成熟度モデルは何をどう測るのか」を順に説明します。

4ページを上から順に読んでください。読み終えると、[成熟度モデル](../model/index.md)の各ページに出てくる用語と考え方を、具体的な場面と結びつけて読めるようになります。

| 順 | ページ | 読み終えると分かること |
|---|---|---|
| 1 | [AIを含む開発とは](ai-development.md) | AIエージェントが開発の中で何をするか。Agent Skill、環境との接続、開発標準資産という三つの言葉が指す具体物 |
| 2 | [開発の基本用語](terms.md) | リポジトリ、MR・PR、CI、WBS、請負と準委任など、本成熟度モデルの説明に繰り返し出てくる開発と契約の用語 |
| 3 | [なぜ成熟度を測るのか](why.md) | AIを導入しただけでは効果が出ない理由と、架空PJで実際に起きたこと |
| 4 | [成熟度モデルの全体像](overview.md) | 制度化レベル、評価軸、自動化段階という三つの概念の関係と、「レベル3／A3」の読み方 |

このサイトの説明では、一つの架空のプロジェクトを例に使います。

| 項目 | 設定 |
|---|---|
| 名称 | 販売管理システム更改PJ（以下「販売管理PJ」） |
| 顧客 | 製造業の販売部門 |
| 契約 | 請負（要件整理から結合テストまで） |
| 体制 | PM 1名、PL 1名、設計者 2名、開発者 5名、テスト担当 2名 |
| 技術 | Java（Spring Boot）と React |
| AI利用の出発点 | 開発者のうち2名が、コーディング用のAIエージェントを個人の判断で使い始めた |

開発経験が十分にある方は、この節を飛ばして[成熟度モデルの全体像](overview.md)から読んでも構いません。
