# 工程別チェックリスト

PJ全体を一つの値で表すと、成熟している工程と未成熟な工程が見えなくなります。実装だけが速くなり、レビューや結合テストが人手のままであれば、後続工程に待ちが発生します。工程別チェックリストは、この偏りを見つけるために使います。

各ページは正本（`criteria/process.json`）から生成しています。

| 工程 | 主な評価対象 |
|---|---|
| [要件整理](requirements.md) | 会議記録、要求、決定事項、未決事項、確認質問 |
| [外部設計](external-design.md) | 画面、API、業務ルール、要件との整合性 |
| [詳細設計](detailed-design.md) | 処理方式、例外、ログ、実装可能性 |
| [実装](implementation.md) | コード生成、ビルド、静的解析、修正反復 |
| [単体テスト](unit-test.md) | テスト観点、テストコード、カバレッジ |
| [結合・システムテスト](integration-test.md) | テスト設計、環境操作、証跡、合否判定 |
| [レビュー](review.md) | 差分取得、指摘、再レビュー、マージ制御 |
| [障害調査・修正](incident.md) | ログ、原因分析、再現、修正、回帰確認 |
| [PM・進捗管理](pm.md) | 進捗集計、遅延検知、品質リスク、報告 |

## タグの読み方

各項目には、どのレベルまたは自動化段階に対応するかを示すタグを付けています。

| タグ | 意味 |
|---|---|
| 開発標準資産の前提 | その工程で再利用できる標準資産があるか |
| レベル1 | 個人がAIでその作業を実施できる |
| レベル2 | Skill、入力、出力、完了条件がPJで標準化されている |
| A2 | AIが共有環境の情報を取得・変更できる |
| A3 | 自動起動、共有CIでの実行・検証・記録ができる |
| A4 | AIが作業を分解し、判断と反復を行う |

タグは初期割当です。工程の判定結果は、あるタグの項目をすべて満たした最上位のタグで表します（例：「実装：レベル2／A3」）。
